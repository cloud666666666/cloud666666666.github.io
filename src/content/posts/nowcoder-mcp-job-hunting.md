秋招进行到现在, 我最大的感受不是"笔试题难", 而是——**信息太散了**。

岗位挂在几百个公司官网上, 截止时间写在各自的招聘系统里, 新开的批次靠公众号和群里转发……每天刷两小时, 还是会漏。前阵子我给自己写过一个"每日职位雷达"脚本(博客里有那篇), 但它本质还是爬虫思路: 我爬我的, 官网改版它的。

所以当我看到**牛客把校招岗位数据开成了一个官方 MCP**的时候, 第一反应是: 这才算"正经接口"。

这篇分享一下我把它接入的过程、它到底能干什么, 以及在哪一步卡了很久——给后面想折腾的朋友省点时间。

## 它能干什么

MCP 是现在 AI 客户端(Claude Desktop / Cursor / 各种助手)通用的工具接入协议。牛客这个官方服务接进来之后, 你的 AI 助手就多了这些能力(实测发现 14 个工具, 挑求职用得上的列):

| 工具 | 能干什么 |
|---|---|
| 岗位搜索 | 按 关键词 / 公司 / 城市 / 学历 / 批次 / 行业 / 公司性质 / **最近 N 天发布** 查校招岗位 |
| 项目搜索 | 按批次 / 行业 / 站点 / 城市 / **截止时间** 筛校招项目 |
| 岗位详情 | 单个岗位的完整 JD + **官网申请链接** |
| 投递记录 | 读取你在牛客保存的投递进展 |
| 简历工具 | 在线简历读取 / 完成度检查 / 简历管理 |
| 申请指引 | 返回岗位的官网申请入口 |

对求职的人来说最有用的是两个点:

1. **"最近 N 天发布"筛选**——等价于"今天有什么新岗位", 数据来自官方库, 不用自己爬;
2. **截止时间字段**——可以真的做到"把这周末要截止的岗位给我列一下", 而不是靠人肉记表。

## 怎么接入(可直接照抄)

牛客提供的是标准的 streamable HTTP MCP, 用 Token 认证。在你常用的、支持 MCP 的客户端里, 配置长这样:

```json
{
  "mcpServers": {
    "nowcoder-skills": {
      "url": "https://www.nowcoder.com/agent/mcp",
      "headers": {
        "Authorization": "Bearer nk-你的Token"
      }
    }
  }
}
```

Token 在牛客那个"技能包页面"(展示 11 个技能的入口)里可以生成。

如果你也用 Hermes(我自用的助手)这类命令行客户端, 几条命令就能加:

```bash
hermes mcp add nowcoder --url "https://www.nowcoder.com/agent/mcp"
hermes config set mcp_servers.nowcoder.headers.Authorization "Bearer nk-你的Token"
hermes config set mcp_servers.nowcoder.enabled true
hermes mcp test nowcoder
```

最后一条 `test` 会返回连接结果和工具清单, 看到 `Tools discovered: 14` 就是通了(实测连接耗时 1.1 秒, 挺快)。

## 实测:搜一把"最近 3 天的新岗位"

接入后我随手试了下:筛选"27 届秋招 + 最近 3 天发布"。返回的单条结构大概是这样(去掉了冗长字段):

```json
{
  "company": "某某科技",
  "title": "算法工程师(J10279)",
  "city": "深圳、成都、杭州",
  "industry": "电子/通信",
  "source": "beisen",              // 数据来自哪个 ATS 站点
  "deadline": "2026-10-30",        // 截止时间字段!
  "publishTime": "2026-09-19T12:36:25.000Z",
  "url": "https://…/campus/detail?jobAdId=…"   // 官网申请链接
}
```

几个感受:

- **有截止时间、能按发布时间过滤**——这俩恰好是我自己写爬虫时最头疼的部分(官网格式五花八门, 时间到处藏);
- **带官网申请链接**——点进去就是申请页, 不用再去搜索引擎里翻;
- 数据标了来源站点(北森 / 国聘 / moka 这些 ATS), 出问题能对到源头;
- 我试的那条宽条件有 **800+ 条命中**(截至发稿时, 数字每天在变), 库不小。

## 踩坑记录:OAuth 走不通, 请直接用 Token

给后面折腾的人省时间的部分。

这个 MCP 服务端同时声明了 OAuth, 我的客户端默认按标准 OAuth 流程走——**卡死**。报错:

```
Registration failed: 400 {"error":"invalid_redirect_uri",
"error_description":"Unsupported redirect URI"}
```

意思是动态客户端注册那一步, 本地回调地址落在它白名单之外。我试了各种形态:

- `http://localhost:<port>/callback` ❌
- `http://127.0.0.1:<port>/callback` ❌
- 连 Claude / Cursor / VSCode 这类客户端的标准回调 ❌

全被拒。结论:它的 OAuth 白名单只放行自家生态的客户端——**第三方客户端目前直接走 Token 方式就行**, 也就是上面那份 `headers` 配置。Token 是标准兼容的, 各客户端通用, 反而比 OAuth 省事。

(顺带:Token 用官方入口生成, 别贴到任何公开地方——这篇里我自己的当然都不会出现。)

## 边界与定位(客观说)

用了几天, 我觉得它的定位是**"岗位库检索器"**, 不是万能药:

- **不是全网**:它自己的说明里也写了, 结果是"本次条件命中数, 不代表全网"。多源交叉还是必要的——我的习惯是它 + 目标公司官网 + 讨论区三个来源对着看;
- **不代替投递**:申请类工具明确"不代提交", 投递还得去官网走流程。这其实是对的——信息可以自动化, 投递得自己认真;
- **数据以官网为准**:它返回的是候选, 投之前点进官网核对一遍截止时间和要求。

## 小结

对求职的人来说, 这可能是今年校招工具里比较值得折腾的一个: 官方数据源、标准协议、筛选维度比网页搜索还全(学历 / 公司性质 / 发布时间都有)。配置一次, 以后"帮我查查这周截止的岗位""搜一下杭州的大模型岗"就是一句话的事。

如果你也在秋招, 找个支持 MCP 的客户端接上试试。踩到 OAuth 的坑别死磕, 翻回上面那份 Token 配置照抄就行。

祝各位都能上岸。
